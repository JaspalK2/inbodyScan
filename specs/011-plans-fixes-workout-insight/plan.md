# Implementation Plan: Plans UX Fixes and Workout Insights

**Branch**: `011-plans-fixes-workout-insight` | **Date**: 2026-04-05 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/011-plans-fixes-workout-insight/spec.md`

## Summary

Five targeted fixes and enhancements to the Plans page: (1) remove the redundant activity level selector and source it from the user profile, (2) fix diet plan day totals by computing them client-side from meal values instead of trusting AI-returned totals, (3) surface saved day plans in "My Saved Meals" and Day Planner views, (4) add a delete capability for workout plans, and (5) add a body-composition-aware "Why this plan?" explanation to generated workout plans. No DB schema changes are required.

## Fix-by-Fix Implementation Guide

### Fix 1: Remove Activity Level Selector (US2)

**File**: `frontend/app/(app)/recommendations/page.tsx`

- Remove `activityLevel` state variable and its setter
- Remove the `<select>` element for activity level (lines ~418-425)
- Read `profile?.activity_level ?? "moderately_active"` from the existing `useQuery(["profile"])` result
- Pass this value directly to `calculateMacros()` and `generateDiet()` calls
- No backend changes required

### Fix 2: Diet Day Totals — Client-Side Computation (US1)

**File**: `frontend/app/(app)/recommendations/page.tsx`

- Extract a helper function `computeDayTotals(meals: Meal[])` that returns `{calories, protein_g, carbs_g, fat_g}` by summing meal values
- Replace all reads of `day.day_totals` in the diet plan display with calls to `computeDayTotals(day.meals)`
- The existing "Live Macro Totals" pattern in edit mode (lines ~569-599) demonstrates this — extract it into the shared helper
- No backend changes required

### Fix 3: Saved Day Plans Visibility (US3)

**File**: `frontend/app/(app)/recommendations/page.tsx`

- The `dayPlans` query (`useQuery(["day-plans"], recommendations.listDayPlans)`) already exists
- In the "My Saved Meals" sub-tab: render `dayPlans` list directly (currently the section only renders custom meals filtered by name)
- In the Day Planner view: read from `dayPlans` query result rather than filtering custom meals by description prefix
- No backend changes required

### Fix 4: Delete Workout Plan (US4)

**Backend** — `services/recommendation-service/src/routers/recommendations.py`:
- Add `DELETE /api/recommendations/workout/{rec_id}` route
- Pattern: load record, verify `rec.user_id == current_user_id` (return 404 if not found/not owned), `await session.delete(rec)`, `await session.commit()`, return `Response(status_code=204)`

**Frontend** — `frontend/lib/api.ts`:
- Add `deleteWorkout: (id: string) => request("recommendation", `/api/recommendations/workout/${id}`, { method: "DELETE" })`

**Frontend** — `frontend/app/(app)/recommendations/page.tsx`:
- Add `deletingWorkoutId` state (string | null)
- On workout plan card: show Delete button; on click set `deletingWorkoutId = plan.id`
- When `deletingWorkoutId === plan.id`: show inline "Confirm / Cancel" buttons
- On confirm: call `deleteWorkout.mutate(plan.id)`, invalidate `["workout-recommendations"]` query

### Fix 5: Workout Plan Explanation (US5)

**Backend** — `services/recommendation-service/src/services/prompt_builder.py`:
- Update `build_workout_prompt()` to add `plan_explanation` to the requested JSON structure:
  ```
  "plan_explanation": "2-4 sentences explaining why these exercises were chosen based on the user's body composition. Reference specific metrics (e.g. lean mass, body fat %). Identify which muscle groups need the most work and which are already strong."
  ```
- The scan metrics already included in the prompt provide the body composition context

**Frontend** — `frontend/app/(app)/recommendations/page.tsx`:
- In the workout plan card display, read `plan.structured_plan.plan_explanation ?? plan.structured_plan.summary`
- Render it as a styled block at the TOP of the expanded plan view, before the day/exercise list
- Style: `glass-card p-3 mb-4` with a small label "Why this plan?" in `text-xs text-muted-foreground`
- Fall back gracefully: if neither field exists, render nothing (no crash, no empty section)
