# Implementation Plan: Plan Editing and Log Fixes

**Branch**: `005-plan-editing-fixes` | **Date**: 2026-04-03 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/005-plan-editing-fixes/spec.md`

## Summary

Four user-visible gaps in the existing recommendation and food-log workflows. Three are frontend-only fixes wiring existing backend APIs to UI entry points that were never connected. One adds a new backend endpoint (exercise search) backed by a CC0 static dataset. No database migrations are required.

| Story | Backend work | Frontend work |
|-------|-------------|---------------|
| US1 — Save meal from diet plan | None (API exists) | Add "Save meal" button to each meal row |
| US2 — Day plans in Saved Meals tab | None (API exists) | Add Day Plans section to saved sub-tab |
| US3 — Apply day plan from Day Planner | None (API exists) | Add "Use saved plan" picker + food log batch call |
| US4 — Exercise search in workout editor | New `GET /exercises/search` endpoint + CC0 JSON asset | Replace text input with inline typeahead; wire to live score |

## Technical Context

**Language/Version**: Python 3.13 (recommendation-service), TypeScript 5.x / Next.js 15 (frontend)  
**Primary Dependencies**: FastAPI, SQLAlchemy 2.0 async, Pydantic v2 (backend); TanStack Query v5, React 18 (frontend)  
**Storage**: Supabase PostgreSQL — no schema changes required  
**Testing**: pytest + pytest-asyncio + httpx (backend); Jest (frontend)  
**Target Platform**: Web (Next.js SSR + FastAPI microservices)  
**Project Type**: Web application  
**Performance Goals**: Exercise search < 1 s; score update < 1 s; day plan apply < 2 s (all from spec SC-001–SC-006)  
**Constraints**: CC0-only exercise data source (constitution Principle III); no new DB migrations  
**Scale/Scope**: Single-user health app; exercise dataset fixed at ~800 items

| V — UI/UX Consistency | Save meal button reuses existing `BookmarkPlus` icon + `Button` component. Exercise typeahead reuses the same inline search pattern as `DietDayRow` food search. Day Plans section in Saved Meals uses the same card/list pattern. | ✅ Pass |

## Phase 0 Research Output

See [research.md](research.md). All decisions resolved:

1. **Exercise library source** → `yuhonas/free-exercise-db` CC0 JSON (bundled in service, filtered in-memory). Live API options rejected — all fail constitution Principle III license gate.
2. **Meal save mapping** → Reuse existing `CustomMeal` / `POST /meals` endpoint; `food_name` = full food string, `quantity_g` = 100 placeholder.
3. **Day Plans visibility** → Frontend-only: add `listDayPlans()` query to saved sub-tab.
4. **Apply day plan** → Frontend calls `createFoodLog` batch for each `DayPlanEntry.items_snapshot`.
5. **Exercise picker UX** → Inline typeahead (confirmed in clarification session, Option B).
