## Implementation Strategy

### Fix 1 — Nested Button (WorkoutPlanCard)
Change outer `<button>` (expand/collapse, ~line 1648) to `<div>` with `cursor-pointer` and `role="button"` styling. Inner `<Button>` (Edit) stays as-is.

### Fix 2 — Diet Plan Deletion
1. Backend: Add `DELETE /api/recommendations/diet/{id}` in `recommendations.py` — mirror `DELETE /splits/{id}` pattern.
2. Frontend `api.ts`: Add `deleteDiet(id)` function.
3. Frontend `DietPlanCard`: Add Trash2 icon delete button in card header with `window.confirm` guard; on confirm call `deleteDiet` and invalidate `["diet-recs"]` query.

### Fix 3 — Sets Field Free Editing (WorkoutPlanCard)
Change `sets: parseInt(e.target.value) || ex.sets` to `sets: e.target.value` in the onChange handler. Change value prop to `String(ex.sets ?? "")`. On save: parse to int with `parseInt(ex.sets) || undefined`.

### Fix 4 — Saved Meals Grouping (FoodMealsTab)
Replace flat list render with two sections:
- **Day Planner Meals**: meals where `name.startsWith("Day Planner — ")`, grouped by day number extracted from `description` (`"Saved from Day N diet plan"`).
- **My Meals**: all other meals, sorted by `created_at` descending.
- If both empty: single empty state. If one section is empty: hide that section.

### Fix 5 — items_snapshot Population (DietDayRow saveDayPlan)
Ensure the `entries` array passed to `createDayPlan` includes `items_snapshot` with individual food items per slot. The code from feature 006 should already do this — verify and fix if not.

### Fix 6 — Workout Prompt Coverage (prompt_builder.py)
Update `build_workout_prompt()` to explicitly require:
- All major muscle groups: chest, back (upper + lower), shoulders (front + side + rear), biceps, triceps, quadriceps, hamstrings, glutes, calves, core/abs
- Minimum 3 sets per muscle group per week
- Include push and pull movements each week
- Include at least 1 cardio or conditioning session per week
- Include compound movements (squat, deadlift, bench, row, press)
