# Implementation Plan: Food Log Quantity Unit Selector

**Branch**: `021-quantity-unit-selector` | **Date**: 2026-04-06 | **Spec**: [spec.md](spec.md)

## Summary

Add a unit selector dropdown (g, oz, lb, ml, piece, cup) next to every quantity
input in the Food Log entry flow and the Custom Meal builder. The frontend
converts the selected unit to grams before submission; both the converted gram
value and the original entered quantity + unit are persisted to the backend for
cross-device display. USDA serving size is used for "piece" when available.

## Technical Context

**Language/Version**: Python 3.13 (backend), TypeScript 5.x (frontend)
**Primary Dependencies**: FastAPI 0.115, SQLAlchemy 2.0 async, Pydantic v2 (backend); Next.js 15, React 18, TanStack Query v5, Tailwind CSS (frontend)
**Storage**: Supabase PostgreSQL — `daily_food_log_entries` and `custom_meal_items` tables extended with two nullable columns each
**Testing**: pytest (backend unit/integration), manual smoke test (frontend)
**Target Platform**: Vercel (serverless) + Supabase
**Project Type**: Web application (microservice backend + Next.js frontend)
**Performance Goals**: Standard web app — unit conversion is purely arithmetic, no latency impact
**Constraints**: Additive schema migration only (nullable columns, no defaults changed); backward-compatible
**Scale/Scope**: Existing user base; single recommendation-service microservice
